# NordLine_Free

Подписка для обхода обычных блокировок, белых списков мобильного интернета и доступа к ИИ (ChatGPT, Claude, Gemini и др.).
Серверы собираются из публичных списков (полный перечень ниже): дубли убраны, названия понятные, серверы разложены по назначению. В основные подписки попадают только узлы со свежей успешной проверкой. Зарубежные серверы идут сверху, российские в самом низу.

## Источники серверов

| Источник | Что берём | Для чего |
|---|---|---|
| [zieng2/wl](https://github.com/zieng2/wl) | `vless_universal.txt`, `vless_lite.txt` | белые списки |
| [igareck/vpn-configs-for-russia](https://github.com/igareck/vpn-configs-for-russia) | `WHITE-CIDR-RU-all.txt`, `WHITE-SNI-RU-all.txt`, `WHITE-CIDR-RU-checked.txt` | белые списки |
| [igareck/vpn-configs-for-russia](https://github.com/igareck/vpn-configs-for-russia) | `BLACK_VLESS_RUS.txt` | обычные блокировки и ИИ |
| [tiagorrg/vless-checker](https://github.com/tiagorrg/vless-checker) | `docs/keys.json` (проверенные ключи) | по меткам `[BL]` и `[*CIDR]` в названии |
| [whoahaow/rjsxrd](https://github.com/whoahaow/rjsxrd) | `githubmirror/bypass/bypass-all.txt` | белые списки и обычные блокировки, не больше 120 лучших |
| [XTLS/Xray-core](https://github.com/XTLS/Xray-core) | программа для проверки серверов | только проверка, серверов не даёт |

Все серверы чужие и публичные. Авторы списков к этому проекту отношения не имеют.

## Какой файл взять

| Что нужно | Файл | Как использовать |
|---|---|---|
| **ОДНА ссылка: авто-сервер + все серверы** | `auto.json` | Подписка в формате Xray JSON (Happ, v2rayN, v2rayNG) |
| Все проверенные серверы | `all.txt` | Ссылка на подписку, любой клиент |
| Белые списки | `whitelist.txt` | Ссылка на подписку |
| ИИ (ChatGPT, Claude, Gemini, Grok...) | `ai.txt` | Только зарубежные серверы |
| Обычные блокировки (YouTube, Instagram...) | `regular.txt` | Только зарубежные серверы |
| Только российские серверы | `ru_only.txt` | Ссылка на подписку |
| Готовый конфиг с авто, белые списки | `clash_whitelist.yaml` | Clash Meta / Mihomo |
| Готовый конфиг с авто, обычный режим | `clash_regular.yaml` | Clash Meta / Mihomo |
| Непроверенный резерв белых списков | `unverified.txt` | Отдельная подписка для ручной проверки в своей сети |
| Тот же резерв для Happ | `unverified.json` | Только отдельные профили, без авто-групп |

## Что в `auto.json` (по порядку)

1. `🌍 АВТО Обычные блокировки`: самый быстрый из зарубежных серверов
2. `🤖 АВТО (зарубежные, ИИ отдельно)`: только зарубежные, домены ИИ идут через серверы, где ИИ доступен
3. `📶 АВТО Белые списки`: серверы, подходящие для белых списков (зарубежные сверху)
4. `🧠 АВТО ИИ`: только серверы, где работают ChatGPT, Claude, Gemini
5. дальше каждый сервер отдельно, российские внизу

Пинг проверяется раз в минуту, при поломке сервера клиент переключается сам.
До первого успешного замера каждая авто-группа использует узел с минимальной
задержкой по свежей проверке сборщика. ИИ-группа выбирает его только среди своих
проверенных ИИ-серверов. Непроверенный резерв в авто-группы не входит.

Во всех JSON-профилях задан DNS: Cloudflare DoH с явным IP в `dns.hosts`.
Это позволяет Happ взять DNS туннеля из JSON. После обновления подписки
переподключись к профилю. Ошибка `balancing strategy returns empty tag`
в старых конфигурациях могла возникать до первых результатов проверки;
в новых конфигурациях для этого задан `fallbackTag`.

В `clash_whitelist.yaml` все группы, ручной выбор и ИИ-маршруты используют
только узлы из белых списков. По умолчанию выбрана группа белых списков.

## Как читать название сервера

`🇩🇪 Германия #3 · 🤖 ИИ · 🌍 Блокировки · 📶 Белые списки`

- флаг, страна, номер сервера в стране
- для чего подходит: `🤖 ИИ`, `🌍 Блокировки` (YouTube, Instagram и т.д.), `📶 Белые списки`
- метки `📶` нет у серверов из списка «только обычные блокировки»: при белых списках они могут не работать
- у российских серверов только `📶 Белые списки`: через них ИИ и заблокированные сайты не откроются

## Как добавить в приложение

1. Скопируй ссылку на нужный файл (см. ниже про хостинг).
2. В приложении: «Добавить подписку» → вставь **ссылку**, а не содержимое.
3. Включи автообновление раз в час.
4. Выбери первый пункт `🌍 АВТО` или `🤖 АВТО` и подключайся.

## Свой хостинг с автообновлением

1. Создай публичный репозиторий на GitHub и залей туда все эти файлы (включая папку `.github`).
2. Вкладка Actions → включи workflow «Обновление NordLine_Free». Раз в час он скачает свежие серверы, проверит их и пересоберёт подписку.
3. Ссылка: `https://raw.githubusercontent.com/<твой_ник>/<репозиторий>/main/auto.json`
   (или `all.txt`, `ai.txt`, `clash_whitelist.yaml` и т.д.)

## Проверка серверов на работоспособность

В репозитории есть `probe.py`: он поднимает Xray и проверяет каждый сервер
HTTP-запросами через отдельный SOCKS-вход. Сначала запрашивается Cloudflare trace,
при неудаче — Google generate_204, затем Microsoft Connect Test. Если весь проход
неудачен, он повторяется один раз. Нужен ожидаемый HTTP-код и ответ контрольного
адреса; произвольная страница с кодом 200 не считается успехом.

Cloudflare дополнительно сообщает страну выхода. Если сработал другой адрес,
страна остаётся из исходного списка — это не проверенная геолокация выхода.
Узлы без известной страны не попадают в основные группы.

- **Автоматически:** workflow запускает проверку каждый час. Результат действителен два часа. Неподтверждённые зарубежные серверы из списка «только блокировки» убираются; узлы белых списков сохраняются в отдельном непроверенном резерве. Внутри страны проверенные серверы идут от быстрых к медленным.
- **Серверы без флага в названии** (часть списка rjsxrd) попадают в подписку только после проверки: страну для них определяет реальный выход. Без проверки они отбрасываются.
- **Лимит:** из списка rjsxrd берётся не больше 120 серверов, поровну по странам, быстрые вперёд.
- **Вручную на своём компьютере:** используй команды загрузки, проверки и сборки из `.github/workflows/update.yml`. Сохраняй типы источников `=bl`, `=auto` и `=cap`: от них зависит принадлежность к белым спискам. Для выбора исполняемого файла curl можно задать `CURL_BIN`.
- **Ограничение:** проверка на GitHub-раннере не показывает, пропускает ли сервер белые списки в вашей мобильной сети. Непроверенные узлы белых списков и российские узлы остаются в `unverified.txt` и `unverified.json`. Их можно проверять вручную; основные авто-группы их не используют.
- **Без свежего `--alive`:** основные подписки будут пустыми, а узлы белых списков сохранятся только в резерве. Валидатор не разрешит публикацию такой сборки.

## ИИ-серверы и Gemini

Метку `🤖 ИИ` и группу `🧠 АВТО ИИ` получает только сервер, через который реально открывается Gemini. Страна на флаге этого не гарантирует: Google смотрит на IP выхода сервера.

- Проверка запускается автоматически каждый час в GitHub Actions: через каждый сервер идёт запрос к Gemini, и если он отклонён по региону, сервер не попадает в ИИ.
- Для надёжной проверки добавь в репозиторий секрет `GEMINI_API_KEY` (Settings → Secrets and variables → Actions). Ключ бесплатный, берётся на aistudio.google.com. Лучше заведи отдельный ключ только для этого. Без ключа проверка менее точная.
- Без свежей успешной проверки ИИ-метка не ставится.
- Если сервер отмечен `🤖 ИИ`, а Gemini не открылся, значит Google поменял правила, и такой сервер надо убрать вручную.

## Проверка перед публикацией

Workflow сначала собирает файлы в `output`, затем запускает `validate.py`.
Он проверяет согласованность списков и счётчиков, подтверждение каждого основного
узла в `health.json`, DNS для Happ и выбор `fallbackTag` по измеренной задержке.
Каждый профиль, включая ручной резерв, проходит `xray run -test`, оба YAML — `mihomo -t`.
Только после успешной проверки файлы копируются в корень и сохраняются в GitHub.

Обновление останавливается при пустом общем, зарубежном или белом списке,
при уменьшении общего списка больше чем вдвое, а также если успешной проверки
серверов нет или она старше двух часов. Предыдущая опубликованная версия сохраняется.
Лимит сокращения списка не доказывает работоспособность отдельных серверов.
При первой миграции со старой подписки без `health.json` лимит сравнивает старый
список с суммой проверенных и резервных узлов: раньше они находились в одном файле.
После миграции лимит сравнивает только проверенные узлы.

Перед push workflow загружает текущий `main` и переносит на него коммит подписок
через rebase. При одновременном обновлении ветки push повторяется до трёх раз.
Если изменился код генератора или возник конфликт подписок, публикация пропускается
с сообщением `Publication skipped`; запусти workflow повторно на текущем `main`.
Принудительный push не используется.

В `stats.json` поле `generated_at` содержит время сборки, а
`last_successful_probe_at` — время завершения проверки с хотя бы одним
успешным сервером. Без такой проверки второе поле равно `null`.
Время записывается в UTC с часовым поясом.
`health.json` хранит статус, время, задержку, успешный контрольный адрес и
неудачные попытки для сохранённых узлов; ключ связан со всеми параметрами подключения.

Локальная проверка: `python -m unittest -v` и
`python validate.py output --previous . --require-probe --xray ПУТЬ_К_XRAY --mihomo ПУТЬ_К_MIHOMO`.
Нужен пакет `pyyaml`. Для теста начальной UDP-маршрутизации задай переменную
окружения `XRAY_BIN`; для теста отказа проверки ядром — также `MIHOMO_BIN`.
Без путей к ядрам эти два теста пропускаются.

Идентификатор проверки сервера теперь включает все параметры подключения.
Старые `probe.json` с прежними ключами нужно пересоздать через `probe.py`;
workflow делает это при каждом обновлении.

## Важно

- Это чужие публичные серверы. Их владельцы технически могут видеть, на какие домены ты ходишь. Не вводи через них пароли от банков и госуслуг без необходимости.
- Серверы живут от нескольких минут до суток, поэтому нужны автообновление и авто-выбор.
- В Clash-конфиги не попадают серверы со сложными XHTTP-настройками. В `auto.json` и `.txt` они есть.
